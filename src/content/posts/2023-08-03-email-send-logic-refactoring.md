## To do

- Email 발송 도메인 평판 개선 및 발송 구조 개선 작업 이전 로직 리팩토링을 수행한다.

### 작업 배경 및 목적

- 도메인 평판 추가 및 발송구조 변경 진행 예정
- 발송구조 변경간 현재 구조를 그대로 이관하는 것보다 약간의 통합을 한 이후 가져가는 것이 유지보수에 더 좋을 것이라 판단
- 분리되어 있는 3가지 타입(일반 발송, 대량 발송, 태그 발송)을 하나의 발송 구조로 가져갈 수 있을 것이라 판단되어 진행

### 작업 전 (설계)

#### 주요 고려사항

- **하나의 method에 전체 로직이 구현**되어 있으니 누락되는 기능이 있는지 꼼꼼하게 체크 필요
  - 서비스 로직 중간중간 세팅해주는 값에 대한 전반적인 확인 필요
- 변경 최소화를 위해 기존 코드를 최대한 활용할 수 있는 방안으로 진행한다.
  - 의존성이 있는 클래스의 코드 변경은 통합이 가능한 것 이외에는 웬만하면 건드리지 않는다. (코드 변경 최소화)
  - strangler fig 패턴 활용

### 서비스 로직 분석

- 메세지 조회
  - 일반, 대량, 태그 메일 조회
- 본문 조회
- 발송 전 필터링
  1. 수신자 거부 목록에 포함된 경우
  2. 도메인 인증이 안된 경우
  3. 이미 차단된 도메인인 경우
  4. 본문 또는 템플릿 파라미터가 null 인 경우
- 메세지 세팅
  1. 읽음여부 URL 추가
  2. 수신 거부 URL 치환
  3. 메세지 ID 생성
  4. SenderDomain 분리해 세팅
  5. 템플릿 치환
  6. 수신자 세팅
- 상태별 업데이트
  1. 유효한 수신자
     - 상태 업데이트 (발송 준비)
     - stats
     - metric (prometheus)
  2. 차단된 수신자
     - 상태 업데이트 (발송 준비)
     - metric (prometheus)
  3. 인증된 수신자
     - 상태 업데이트
     - stats
     - metric (prometheus)
- 메일 발송
  - smtp 세션 생성
  - 메세지 구성
    - CustomHeader 설정
    - ImageTag 추가
    - 도메인 회신 가능여부
    - 첨부파일 조회
  - 메일 발송 처리

### 구현 방안

- 가장 보편적인 일반 발송의 형식으로 메일 발송처리 진행
  - 대량 메일, 태그 메일은 데이터를 쌓는 구조만 다를 뿐 실제 발송 처리되는 로직은 별반 다르지 않다.
  - 모든 메일 유형은 발송하기 이전 MailInfo 클래스로 세팅 후 CustomMimeMessage로 구성하도록 수정한다.

1. 모든 메일 유형을 MailInfo 클래스 하나로 통합한다.
2. 역할별로 분리한 기능들을 클래스로 분리해 개발한다.
3. MailInfo를 토대로 발송 요청 처리를 수행한다.

### 기대효과

- 클래스 분리 이후 sender로 이관할 로직이 명확해짐
  - ex) 본문 조회 이후 발송로직 가져오기
- 테스트 용이성
  - 테스트 코드 작성이 보다 더 쉬워질 것으로 예상
- 발송 패키지 통합 (유지보수 용이)
  - 기존에 분리되어 있던 발송 패키지를 하나로 통합해 가져간다.
  - 현재 email에는 하위 패키지가 너무 많아 같은 행위를 하는 패키지를 통합하여 좀 더 간결한 구조로 만들고자 함
  - 코드 수정간 3개의 메소드에 추가하던 과정이 1개로 통일된다.

### 변경 기준

  - 추후 분리간 영향도가 최소화되도록 고려
- 역할별 분리
  - 절차지향적으로 수행되던 내용을 그룹화하여 클래스화

## 변경 설계

### 조회 및 업데이트

- 개별 인터페이스로 분리
  - 조회 <= 배치에서 메일 조회할때만 사용
  - 업데이트 <= SMTP 응답결과 업데이트간 사용

![](/images/email-send-logic-refactoring/img-01.png)

### 발송 호출

- 전체 비동기로 수행하도록 변경
- smtpSendManager가 메세지 구성 후 smtpHelper 로의 발송 역할 수행
- ConfigureMailInfo: 메시지 구성 인터페이스
  - 읽음 url 추가, 템플릿 파라미터 매핑 등 작업 수행

![](/images/email-send-logic-refactoring/img-02.png)

### 발송 처리

- 메세지 구성 -> 메세지 구성 클래스 별도 생성
- 첨부 파일 -> 첨부파일 구성 클래스 별도 생성
- 도메인 회신 가능여부 -> 공통 클래스 EmailAddressValidator 사용
- CustomHeader 설정 -> 헤더 설정

![](/images/email-send-logic-refactoring/img-03.png)

## 변경 작업

1. 기존 로직 유지

4. 점진적으로 신규 로직으로 트래픽을 넘겨 최종적으로 과거 발송 Job 제거
